# Mould prototypes, round 1: shared brief (2026-11-08)

Scott (the owner) played the Mould demo (`cargo run --release --bin mould`, code `src/mould/`) and called it the most promising of eight prototypes. Five brainstormers wrote up where it could go (`../theme.md`, `../out-there.md`, `../near-term-challenges.md`, `../toy-feel.md`, `../research.md`; read `../context.md` first, then only the parts of the others your brief names). Scott picked two ideas to prototype side by side: **The Wanderer** and **Mould Organ**. Each is the *cheapest test of its question*, not a full game. He will compare them on a page of pictures with counts.

## Rules for both

- Work in your own git worktree (you were started in one). Commit on a local branch there with a clear message that carries the measurements. **Do not push** and do not open a PR: the thread owner merges your branch into theirs. Never `git add -A`; stage explicit paths. Never run destructive git (force, reset --hard, checkout -- .).
- Read `CLAUDE.md` at the repo root first (the two laws: an outcome is a spread; every verb must deliver something visible). Scott has waived the report / dead-ends / stats / trace process rules for prototypes, but **not** "show it": you must produce pictures.
- Do not edit shared engine files (`src/sim/**`, `src/render.rs`, `README.md`, `Reports/dead-ends.md`, `Reports/open-bugs-handoff.md`). Keep to the files your brief names plus new ones. If you add an `examples/*.rs`, add its row to `Reports/instruments.md` (docscheck gates it). If you add a `src/bin/*.rs`, add it to the arcade's GAMES list only if that is one line (`src/bin/arcade.rs`).
- Build only what you need: `cargo build --release --bin X --example Y`. Building all examples takes 30+ minutes. Before you finish, run `cargo test --release --lib mould` (and your own module), and `cargo clippy --release --locked --bin X --example Y -- -D warnings` on what you touched, and report both results honestly.
- Deliverables go in `/mnt/project-files/game-design/mould-game-brainstorm-2026-11-08/prototypes/<your-name>/`: a short `result.md` (what you built, how to run it, the counts, what you'd do next, what didn't work), plus PNG contact sheets and/or a GIF (mouldprobe already writes GIFs and sheets: read `examples/mouldprobe.rs`). Put the **discrete event count** beside each picture in result.md. That folder is a network mount: re-read a file about 10 s after writing it. Keep pictures under ~3 MB each.
- Keep it deterministic (same seed, same result). Keep frame cost in view: quote mean and worst frame ms if you change what runs each step.
- Writing for Scott: plain world words, answer first. Your final report back should lead with the verdict (does it feel promising, with the numbers), then the branch name and head SHA in your worktree, then the file list.
